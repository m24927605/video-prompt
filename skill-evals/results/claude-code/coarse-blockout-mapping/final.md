以參考素材生成單一 clip:黃昏時分,一名信使穿過石門走進市集,把唯一一封信滑到守衛面前的桌面中央;守衛全程留在桌後。@Video 1 是粗粒度 blockout,只作為動作與攝影機的結構藍圖,不作為畫面外觀來源。

[精確實體]

@Image 2 = 守衛的完整人物參考,作用於整個 clip。

  不繼承:該圖的姿勢、背景、構圖、裁切、光線、圖中其他人物。

@Image 3 = 場景材質與光線參考,作用於整個 clip。
  繼承:石門的造型與石材質感、市集攤位與地面的材質、黃昏光線氛圍。
  不繼承:該圖的構圖與取景、圖中任何人物、任何會覆蓋 blockout 空間配置的場景布局。

[物理]
信封與桌面持續接觸,滑行時不彈起、不翻面、不變形;停下後靜置於桌面中央。信使放手後手中無物。

守衛:雙手保持在桌後,信封滑近時手指微收但不抬手,眉頭不動,只以視線追蹤。兩人皆無對白。

## 驗收檢查(可逐條 yes/no)

- 畫面恰好兩人、一封信、一座石門、一張桌子,無多餘人物或重複道具。
- 信使外觀與 `@Image 1` 一致、守衛與 `@Image 2` 一致;兩人未互換身分。
- 人物路徑、相對尺度、機位運動與 cut 時點跟得上 `@Video 1`;畫面中無任何灰模、guide lines、座標軸或 viewport 痕跡。
- 信封全程貼桌滑行並停在桌面中央;守衛未離開桌後、未接信。
- 光線為黃昏暖光且與 `@Image 3` 材質語彙一致;無對白、無字幕、無 BGM。

## 失敗風險

- **blockout 外觀滲漏**:灰色材質或簡模輪廓混入成片,是 coarse blockout 最常見的失敗。
- **身分互換或第三人**:紅/藍映射錯置,或市集背景自行生成路人。
- **cut 節奏不被尊重**:平台把多 cut blockout 平滑成一鏡到底。
- **滑信物理失真**:信封彈跳、翻面或直接瞬移到桌面中央。

## 修訂階梯(每次只動一個變數)

1. 若灰模滲漏 → 在「不繼承」清單加強對應排除語句(其餘不動);仍失敗則改用首幀圖鎖定開場外觀。
2. 若身分錯置 → 在實體區塊補「紅=信使、藍=守衛」的一句重申。
3. 若 cut 被抹平 → 在攝影機區塊逐一列出 cut 的語意順序(仍不寫死秒數)。
4. 若滑信物理失敗 → 把「滑信」拆成獨立近景插入鏡頭,主 clip 只保留放信動作。
5. 同一缺陷在單變數修訂後仍存在 → 停止加長 prompt,改走拆鏡或後製路線。
