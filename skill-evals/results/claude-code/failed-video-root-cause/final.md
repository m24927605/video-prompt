## Root-cause hypotheses（按上游順序排序）

**H1（最可能）：首幀狀態與實體約束未鎖定（entity/state 層）**
- 支持：00:00 桌上「已經」有兩把鑰匙、她「已經」在畫面內且在錯誤側——這是典型的「prompt 只描述了動作過程，沒描述第 0 幀該長什麼樣」的失敗：模型自行填補開場狀態。第三把鑰匙憑空出現也符合缺少「禁止其他鑰匙」排除條款的模式。
- 不利：未見原 prompt 全文，無法確認是否真的缺首幀描述——此為假設。

**H2：銀幕方向／空間規格缺失（space/camera 層）**
- 支持：起點側完全相反，可能缺「首幀她位於畫面左緣、鏡頭側」的空間錨定；也可能受參考圖鏡像影響。
- 不利：無參考素材與參數資訊可查證。

**H3：手部接觸互動超載（physics/hands 層）**
- 支持：左右手錯置 + 穿模是手部接觸類的典型失敗。
- 註：此為 H1/H2 的下游問題——上游狀態錯了，修手部細節無意義，故排第三。

## 路線決策：**Regenerate**

- **不選 accept**：三個 Critical hard gate 失敗。
- **不選 edit/repair**：無任何可用區間——方向反、結尾反、道具增殖貫穿全片，沒有「局部」可修。
- **不選 VFX**：要同時擦除兩把鑰匙、修穿模、翻轉方向、重做結尾視線，成本遠高於重生成，且核心合約本就在生成層失敗。
- **選 regenerate**：仍存在一個可測試的上游修正（首幀狀態鎖定），符合「模型可勝任的核心合約失敗 + 剩一個可測變因」的重生成條件。

## 停止條件

- 加入首幀狀態鎖定後，**同一缺陷（鑰匙增殖或方向反轉）在 3 次隔離重試內仍存活** → 停止整鏡重生成，拆成兩鏡：①走位鏡頭（入場到桌前）＋②手部特寫 insert（右手放黃鑰匙於桌中央），必要時放置動作走 VFX/實拍合成。
- 若修好鑰匙數卻反覆弄壞另一必要項（如結尾視線）→ 出現震盪即停，改拆鏡。
- 達到專案的重試/預算/時間上限即停，並記錄最後檢查點與已測假設。
